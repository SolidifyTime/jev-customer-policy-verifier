## 每行格式

JSONL 每行是一个独立 JSON 对象，字段与原始、合成数据一致：

```json
{
  "id": "样本管理编号",
  "policy": "业务规则",
  "conversation": ["历史发言1", "历史发言2"],
  "candidate_response": "待判断的客服回复",
  "label": "compliant",
  "metadata": {"source_type": "original", "split": "train"}
}
```

上面仅展示结构，实际 `metadata` 完整保留原始来源、分组、生成模型、提示词版本及已有复核信息。

当前采用 SemIf-OpenJev Direct 输入协议：这三个业务字段构成证据，和固定 criterion、A/B 选项组成一条非思考 chat prompt。A=`compliant`，B=`violating`；读取原生预训练词表头最后位置的 A/B logits，并仅对二者归一化。训练目标是两项交叉熵，Brier 仅用于评测。训练路线改变不修改以下冻结数据文件、字段、哈希或分区。

模型输入**只使用 `policy`、`conversation`、`candidate_response`**。`label` 是训练目标；若需要数字类别，固定 `compliant=0`、`violating=1`。`id` 和 `metadata` 只用于管理，不能拼进模型输入，部分编号及复核字段本身含有标签信息。场景分析、生成说明和审核结论也不作为模型输入。

统一训练文件按样本 ID 排序后，使用固定种子 `20261002` 混排，避免原始数据和合成数据各自连续堆在一起。没有重新划分训练、验证或测试。验证、测试文件与原始固定分区逐字节一致。

## 构建与验证

在项目目录运行：

```sh
python3 scripts/cpv.py data build
```

脚本离线读取既有文件，校验原始文件和分区哈希、来源分组、标签与字段，剔除指定源标签，按“规则＋历史＋回复”规范化精确去重。原始数据优先保留；相同输入的标签冲突会报错。同组或相同完整输入跨分区也会报错。本次合并没有发现额外重复或标签冲突。

构建结果已重新读回核对：7,227 条与输入应保留记录逐项一致，所有来源和复核元数据保留。两个排除标签均不在训练文件，基线文件恰好是统一训练文件的原始部分；各文件哈希与 manifest 一致。重复执行构建，输出逐字节相同；已有目录中的内容不同时会拒绝覆盖。

合成变体中 3 条具有本批抽查标记，其余 4,782 条仍标记未逐条复核，不能把这份文件称作逐条人工标注数据。首轮应在同一验证、测试集上比较原始基线与加入合成数据的效果，结果尚待训练实验确认。
