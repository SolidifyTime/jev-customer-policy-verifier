# 数据构建踩坑记录

文档状态（2026-10-03）：本文保留预试验与提示词迭代中的历史经验。全量生成、7,227 条训练文件和训练入口准备已完成，见[全量完成检查](../reports/bulk-completion-20261003.md)和[训练数据说明](../data/training-data.md)；尚未租用 GPU 开始真实模型训练。下面的实验数字均有对应批次，不能作为最新全量统计。

更新日期：2026-10-02。本文记录已在本地试验中实际遇到的问题，以及当时采用的处理方式。数字来自[两样本预试验](../reports/local-pilot.md)、[首批 50 条报告](../reports/batch-50-report.md)和[多次生成报告](../reports/multi-generation-report.md)；原始样本、请求与模型输出保存在 Git 忽略的 `data/`、`runs/` 目录中。**“通过程序检查”只表示进入待复核队列，不表示标签正确或可以用于训练。**

## 1. 先划分数据，再做任何生成

源文件有 1,982 对正反例，展开后是 3,964 个候选，但它们只来自 498 个 `orig_conv_id`。按样本行随机划分，会让同一原始对话的不同截取、合规与违规回复跨越训练和评测分区。我们先按 `orig_conv_id` 固定分组划分，之后只对训练区调用生成 API，并保存源文件哈希与分区清单。

**仍未解决：**跨区近重复检查尚未完成；分组 ID 是否覆盖全部上游关联也还需要核查。因此目前只能说完成了按已提供原始对话 ID 的隔离，不能声称已经排除所有关联泄漏。

## 2. 来源引用准确性成了提取阶段的主要瓶颈

首批 50 条源样本里，28 条在场景提取阶段被拒。25 条至少有一处规则“引用”不是规则原文的连续逐字片段；其中 10 处只差空格或换行，另 21 处出现拼接、删符号、省略或改写。拒绝它们保护了事实可追溯性，但这不等于 28 条的业务语义都错了。

**处理与经验：**继续要求可定位的原文依据；提取提示词在 `pilot-v8` 中已提供可复制的规则短句，让条件和动作分条引用，5 条定向复测均通过程序核对，后续 v10 保持这份提取内容，但仍有业务解释错误，见[提示词复测](extraction-prompt-update.md)。不要为了提高表面通过率直接关掉引用检查。提取阶段应单独报告“引用格式失败”和“事实或标签不成立”，避免混为一谈。

## 3. JSON 模式不等于结构正确

Flash 的 JSON 输出仍可能多出 `expected_label` 等字段、缺少必需字段，或把请求中的结构说明当作答案返回。两样本预试验中，默认推理模式还出现截断和结构回显。首批首次生成的 22 次调用里，有 4 条输出多余的 `expected_label` 字段；追加生成也出现缺失 `generation_note` 和回显输入字段的情况。

**处理与经验：**生成时关闭推理，固定提示词与参数，本地按预期 schema 检查字段、类型和额外字段；把失败输出与用量保存下来。提示词遵循情况和输出可解析性需要分开统计，不能因为返回了合法 JSON 就直接收样本。

## 4. “有变化”不等于有新增信息

首批首次生成中，6 条对话完全没改；追加生成的 44 条里，19 条对话完全没改。更隐蔽的是源行 554：对话只改变空白字符，旧检查却将其算作“已改写”。新增空白归一化检查后，首轮通过程序检查的历史数字从 12 修正为 11；追加生成中另有 2 条因此被拒。源行 1906 的首轮候选改变了对话，但回复未变，新增信息量也有限。

**处理与经验：**同时检查原样本和同源既有变体的精确重复、空白变化与回复变化。即使文本不同，也要区分真正的场景表达变化和几乎没有训练增量的改写；候选数不能直接写成有效新增样本数。

**后续复测：**增强保留约束的 v9 在 12 次生成中有 10 条完全照抄历史；v10 将历史改写要求前置、缩短提示词后，12 条中 11 条通过程序检查。不过源行 1906 的两个输出只有问候不同，精确去重不会拦住这种近重复。需要兼顾忠实改写与表达多样性，不能只看程序通过数，详见[生成提示词复测](generation-prompt-update.md)。

## 5. 细小措辞变化会改变合规判断

源行 481 的原回复要求“全名、账号 ID **和**订单 ID”，生成回复变成“全名**或**账号 ID，再加订单 ID”；追加生成又复现了同一漂移。源行 554 的原回复跳过会员级别、询问购买日期，生成回复改为询问会员级别，原预期违规标签因此可能翻转。源行 1403 的变体额外增加“不能给折扣”的主张，超出了原回复。

**处理与经验：**生成提示中明确保留 `and/or/if`、例外、动作先后和回复核心主张；复核时对照原规则、原对话、原回复与新样本。尤其不能把“原标签”直接复制给变体。程序检查只能抓住格式和部分重复，无法证明语义保留。

**后续复测：**v10 明确要求保留同一违规点、未知信息及动作对象。6 个已人工确认通过的源场景各生成两条后，资料“且变成或”和发货询问范围改变仍各出现一次，另一条把客户未知的退款进度改成已发送退款的前提。这 3 条均通过程序检查，说明明确指令仍不能保证语义保留；本轮新候选未加入既有 15 条接收样本。

## 6. 原始标签也可能需要重新理解

源行 1476 的回复称“身份已核验”，但对话只显示提供了身份资料；回复还问客户是否发货，而规则要求检查运输状态。源行 1028、1706、599 也在首轮复查中暴露了标签或当前动作含义的歧义。这些问题可能来自原始样本、规则解释或提取过程，不能仅凭变体文本修补。

**处理与经验：**把“资料已提供”和“身份已验证”、 “询问客户状态”和“查询系统状态”区分开。源样本有疑问时先隔离该场景，不继续批量扩写；保留疑问和复核结论，而非静默改标签。

## 7. 模型自动审核并不构成可靠的放行条件

首轮模型自动审核从 12 条程序候选中保留 7 条，拦住了源行 554 的标签翻转，却漏掉源行 481 的“且”变“或”。事实保留审核也曾对明显改变回复动作的样本给出 `pass`。因此，两次模型调用不能视为对标签和事实的一致性保证。

**当前取舍：**模型自动审核默认关闭。用户已完成首批人工最终复核，31 条中接收 15 条，见[人工复核报告](../reports/manual-review-report.md)。后续候选先过程序检查，再每批默认抽查 3 条，重点检查标签和影响判断的事实，不再要求完全等义；抽查者及未逐条复核状态明确记录，见[少量抽查与导出说明](../guides/spot-check-guide.md)。

## 8. 多次生成提高候选数，也会重复放大错误

一份场景结构可以复用：22 份通过提取程序检查的结构各追加生成 2 次，共 44 次调用，新增 20 条通过当前程序检查的候选。加上按新检查重算的首轮 11 条，两轮共有 31 条待复核候选，但只覆盖 15 个源场景，不能视为 31 个独立业务案例。新增 20 条按标签分为合规 13、违规 7，筛选后也并不完全平衡。

**处理与经验：**多次调用时始终以原规则、原对话和原回复为事实来源；前一条生成结果只能用于避免重复，不能成为新事实。先核查值得扩写的源场景，再限制每个源场景的保留量，并按标签、业务类型和来源统计覆盖。随后人工最终复核接收了 15 条（合规 8、违规 7），覆盖 7 个源场景；另有 12 条拒绝、4 条待定，均未导出到通过集合。

## 9. 本地运行需要留下可恢复的证据链

首批 50 条运行期间发生过 3 次 TLS 连接中断；因为每阶段请求、响应和 API 用量单独落盘，续跑没有重复调用已保存的阶段。首批 96 次成功调用的 API 报告费用约 $0.00923；追加生成 44 次约 $0.00415。费用是试验记录，不代表每条最终有效样本的成本。生成由远程 API 完成，Mac 负责准备数据、调用、检查和记录。

**处理与经验：**固定源文件哈希、分区、模型、提示词版本和参数；按阶段缓存结果、设置调用次数及费用上限。`.env` 是访达默认不显示的隐藏**文件**，保存密钥并被 Git 忽略；文档和日志不应写入密钥。原始数据、生成数据及运行记录也不直接提交到仓库。

## 10. 提示词静态正确，仍需真实端到端小试

2026-10-03 的三源实调中，v10 虽然明确禁止待发送回复混入历史、禁止将模糊 2FA 细化为设备，模型仍犯了这两类错误。v11 增强历史来源边界，并把生成输入从 `verified_scene` 改为 `extracted_scene`，明确场景摘要可能有错、原始对话才是事实依据。新增具体例句又被模型抄进不相关场景，v12 因此移除提取中的答案式例句，改用通用规则。

最终生成没有沿用设备细节，但提取解释仍有一次过度具体化；9 条程序候选中另有 3 条仅问候不同的近重复，已由助手记录剔除。36 次小试逻辑调用合计报告费用 $0.003310924，其中一次 429 自动退避重试成功。完整结果见[启动前验证](../reports/bulk-preflight-20261003.md)。

**处理与经验：**脚本测试、格式通过和真实内容质量是三个不同层面的证据。少量实调用于暴露问题；不要把模型提取直接称作已核验事实，也不要将带具体答案的提示例句写成通用填空命令。发现的剔除项按输出哈希保存，后续导出自动跳过，不扩大为全量人工审核。
