# 场景提取提示词调整与小样本复测（2026-10-02）

文档状态（2026-10-03）：本文记录 `pilot-v7/v8` 的历史定向复测；后续提示词已推进到 `pilot-v12`，见[启动前验证](../reports/bulk-preflight-20261003.md)。全量生成、7,227 条训练数据和训练入口准备已完成；尚未租用 GPU 开始真实模型训练，见[训练数据说明](../data/training-data.md)。

本轮只调整第一次 API 调用的场景提取提示词，使用现有 Flash 配置：关闭推理、温度 0.2、输出上限 1,800 token。输出 JSON 字段保持原样；没有重新生成变体、调用模型审核或修改已完成的人工审核与 15 条接收样本。

## 做了哪些调整

1. **短原文引用。**在输入中提供从规则原文逐行提取的 `policy_quote_options`，要求每个 `rules.quote` 直接复制其中一条，条件和动作分条记录；逻辑关系放在 `meaning` 中表达，避免模型拼接或改写长引用。
2. **历史事实与当前回复分开。**`known_facts`、`dialogue_progress` 只描述历史；待审核回复中的承诺、错误主张和核验声明放在 `response_claims`。区分“资料已提供”和“核验已完成”，保留“可能、打算”等不确定或未执行的措辞。
3. **原标签作为待核查标注。**删除“保留给定标签”的提取要求，改为根据实际回复和规则检查标签，禁止为标签强行找理由；正确中间步骤无需一次完成整个流程，条件未知时不能认定对应分支动作已经必须执行。

该轮完成时整体版本为 `pilot-v8`，位于 `src/customer_policy_verifier/generation/pilot.py` 的 `extraction_request()`，该轮未修改生成与审核提示词。后续生成提示词调整将整体版本推进到 `pilot-v10`，提取内容保持本轮 v8 原样，详见[生成提示词复测](generation-prompt-update.md)。复用历史场景仍可通过 `src/customer_policy_verifier/generation/expand_scenes.py` 读取，并按真实来源版本记录。

## 改善与剩余限制

助手逐条查看 v8 输出后，观察到源行 539 已将核验完成状态放入未知信息，并将当前核验声明单列为回复主张；源行 1706 的回复主张改为查询意图，没有继续断言已完成某项查询。规则解释本身也较少混入已经发生的事件。

**程序通过不代表业务解释全部正确。**源行 1028 仍被解释成违规，甚至新增“不能同时询问姓名和订单 ID”的限制，与已填写的人工审核结论冲突；其事实释义还推断邮件可能包含错误信息。源行 1403 的标签理由仍可能把未知会员分支当作当前必需步骤。v8 只能认为改善了引用可解析性及部分事实边界，不能声称完全解决原标签偏置或规则理解错误。

这 5 条是针对已知问题的定向复测，不是随机质量评估。原始记录位于 `runs/archive/extraction/extract-v7-20261002T080443Z/` 和 `runs/archive/extraction/extract-v8-20261002T080904Z/`，包含选样、实际请求、输出及用量。

本轮提示词调整到此收尾。继续沿用人工审核决定和已知问题排除记录，不把复测的 `can_expand=true` 覆盖到既有审核结果。首版后续优先推进训练、固定划分评测和演示，进一步语义提取优化留作改进项。
