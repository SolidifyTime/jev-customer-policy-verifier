这些数字只说明多次调用确实增加了**候选**，不代表得到 31 条可用训练样本。初步查看发现源行 481 的追加变体仍把“全名、账号 ID 和订单 ID”改成了“全名或账号 ID，再加订单 ID”；源行 1476 的两个追加变体仍受原始标签与动作含义疑问影响；源行 1706 有一条回复完全未改。源行 554 的两个追加输出还把原违规询问改为询问会员级别，且对话仅有空白变化，现均被程序拒绝。其余候选仍需逐条检查关键事实、条件关系、回复主张及标签，不能直接继承原标签。

当时采用的简化流程是：提取一次场景结构 → 对同一场景小批量多次生成 → 程序去重与格式检查 → 逐条复核拟入选的少量变体。场景结构本身若有误，重复生成会放大同一错误，因此应先复核准备扩写的来源。多次生成时限制每个源场景的保留数量，并关注合规与违规标签的比例。若最终复核通过数量不足，先完成原始数据基线训练，不把候选数写成有效数据量或性能收益。
