# 少量抽查与轻量导出

后续批次使用 `src/customer_policy_verifier/review/export_candidates.py`：程序检查和去重后，**默认每批只抽查 3 条**，其余样本带“未逐条复核”标记导出，供训练实验使用。可用 `--spot-check-count 2` 将抽查减至两条；候选不足时只抽现有数量。整个导出与回填过程不调用模型 API。

2026-10-03 的全量导出已完成：4,785 条中 3 条由助手抽查、4,782 条未逐条复核，并已进入[统一训练数据](../data/training-data.md)。下方用于新的导出目录；已有结果保持原样。

## 操作方式

在项目目录执行，将已完成的生成批次导出为候选和简短抽查清单：

```sh
python3 scripts/cpv.py review export runs/generation/expand-实际运行时间戳 \
  --output-dir data/derived/本批名称
```

也支持 `batch-...` 目录，或一次传入多个已完成批次。各输入合并后只抽 3 条，并统一做空白归一化后的精确去重。固定种子下抽查结果可复现，优先覆盖合规、违规两类，再尽量覆盖不同源对话。

打开输出目录的 `spot_check.md`。每条只需填写一项结论；剔除或待定时补一句备注：

```text
结论（通过／剔除／待定）：通过
备注：无
```

判断新样本本身的预期标签是否成立，以及是否新增会影响判断的事实。普通措辞、语气或不改变标签的改写差异可以通过，不再要求完全等义。无法迅速判断时填“待定”，本次就不使用该条。

回填后生成训练实验用变体文件：

```sh
python3 scripts/cpv.py review export --output-dir data/derived/本批名称 \
  --apply-spot-check
```

若由助手实际阅读并填写抽查结论，使用 `--reviewer assistant`，避免将助手抽查记为用户人工复核。抽查发现个别问题时，仅移除该条“剔除／待定”样本并记录批次有问题，不自动增加人工抽查量。通过项和未抽中项均可进入实验文件，二者保留各自质量状态。

## 输出文件

| 文件 | 用途 |
| --- | --- |
| `candidates.jsonl` | 通过程序检查的候选，标签继承自源样本，初始均未逐条复核 |
| `spot_check.md` | 默认 3 条抽查清单，含规则、原始材料、新样本和简短结论栏 |
| `training_variants.jsonl` | 回填后供训练实验使用的变体，移除抽查剔除和待定项 |
| `spot_check_results.json` / `spot_check_snapshot.md` | 实际抽查结论、抽查者、移除项及填写快照 |
| `manifest.json` / `summary.json` | 来源与文件哈希、抽样种子、数量和检查结果 |

每条变体的 `metadata.review_status` 区分 `spot_checked` 与 `not_individually_reviewed`；批次抽查数量和抽查者也会记录。**3 条抽查是低人工成本的粗略检查，不是整批样本准确率的证明。**未抽中项可能仍有标签噪声或近重复，实验报告须保留这个限制。

程序继续检查源数据及冻结分区、只导出训练区后代，并沿用当前格式、轮数、占位符、改写及精确去重检查。已知原标签错误或不确定的源候选继续排除；已被首批人工审核拒绝或暂缓的同一份生成文件不会被重新放入候选。旧的逐条复核入口保留用于读取历史记录。

新导出目录应为空。已完成抽查的文件不会被覆盖；需要重新处理时使用新目录。
