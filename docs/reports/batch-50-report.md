# 首批 50 条训练源样本试验（2026-10-02）

文档状态（2026-10-03）：这是 `pilot-v6` 首批实验的历史报告。后续已调整提示词与质量流程，完成全量生成并准备 7,227 条训练数据，见[全量完成检查](bulk-completion-20261003.md)和[训练数据说明](../data/training-data.md)。训练入口已准备，尚未租用 GPU 开始真实模型训练；下文判断仅针对本轮旧方案。

本轮按冻结的 `orig_conv_id` 分区，只从训练区选了 50 条源样本，每条最多生成 1 个变体；提取被拒时不调用生成。合规和违规各 25 条，覆盖 50 个不同原始对话组及 50 种业务意图。固定使用 OpenRouter `qwen/qwen3.7-flash`、关闭推理、温度 0.2、最大输出 1,800 token、提示词 `pilot-v6`。完整选样、逐阶段请求与输出、API 用量、自动保留及拒绝原因保存在本地忽略目录 `runs/archive/batch/batch-20261002T044310Z/`。运行时三次 TLS 连接中断，均从已保存的阶段续跑，没有重复调用已落盘的阶段。

## 阶段结果

| 阶段 | 进入 | 通过 | 拒绝 | 主要原因 |
| --- | ---: | ---: | ---: | --- |
| 场景提取 | 50 | 22 | 28 | 25 条源样本至少有一处规则“引用”不是原文的连续逐字片段 |
| 变体格式与机械检查 | 22 | 12 | 10 | 6 条对话完全没改；4 条输出了多余的 `expected_label` 字段；原因可重叠 |
| 事实保留＋独立判断 | 12 | 7 | 5 | 有材料不足、合规判断不一致或核心主张变化 |

自动保留率是 **7/50（14%）**，其中合规 **5/25**、违规 **2/25**。这些 7 条仍是待复核候选，未加入训练集。共调用 API **96 次**，API 报告费用 **$0.009229866**；按 7 条自动保留候选计算约 **$0.001319/条**。这不是最终合格训练样本的成本。

规则引用失败共出现 31 处、涉及 25 条源样本。其中 10 处只差换行或空格，另 21 处将条件和动作拼接、删去符号、用省略号或改写措辞。严格引用检查在这些情况下拒绝了扩写，符合“事实须可追溯”的要求；但它让通过率主要受提取格式影响，不能直接把 28 条提取拒绝解释为 28 条语义错误。下一轮应让模型分别返回条件和动作的短原文片段，继续逐字核对，而不是直接放宽引用检查。

## 自动审核复查

逐条查看 7 条自动保留候选后，发现：

- 源行 **481 / `manage_upgrade`**：原回复索取“全名、账号 ID **和** 订单 ID”，变体改为“全名 **或** 账号 ID，再加订单 ID”。两者都可能合规，但回复主张的条件关系改变，保留性审核却给出 `pass`。本条应暂时排除。
- 源行 **1476 / `status_payment_method`**：原回复和变体都声称身份已核验，但对话只显示收集了资料；两者都询问客户是否已发货，而规则写的是“检查订单运输状态”。这首先需要核查源样本标签与动作含义，暂时隔离。
- 源行 **1906 / `promo_code_out_of_date`**：对话确实改写，待审核回复完全没改。标签与违规点保留，但新增信息量有限，应在去重和混合比例决策时单独计数。
- 其余 4 条（源行 112、1161、305、1513）在本次助手逐条检查中未见明显关键事实或标签漂移；仍需按方案由人复核，不能据此直接认定为正式训练数据。

5 条自动审核拒绝中，有一条（源行 **554 / `return_size`，批次序号 33**）生成回复把原先跳过会员级别的违规询问，改成了询问会员级别的合规下一步。事实保留审核却给出 `pass`，独立合规判断给出 `compliant`，最终因与预期违规标签不符而被拒。这证明双重审核拦住了一个标签翻转，也表明事实保留审核单独使用不可靠。另外四条独立判断为 `uncertain`，提示部分原始标签或当下动作的合规性本身需人工核查。

## 当时的判断

Flash 能以较低 API 费用完成本地批量调用，但这套提示词与审核规则的自动保留率只有 14%，且自动保留中仍有关键条件关系漂移。**本轮结束时，不宜直接扩量或用这些候选训练。**原文引用格式、“且／或”条件关系和疑似源标签歧义是后续数据构建需要处理的问题；首版实施范围调整见下文。完整跨区近重复审计与使用许可复核仍未完成。不要改动本轮输出，以保留对照记录。

本地 `runs/archive/batch/batch-20261002T044310Z/review_queue.md` 并排列出了 7 条候选的规则、原对话、变体、未知事实及两道审核理由，方便逐条人工复核。该文件包含源数据内容，因此留在 Git 忽略目录中。

## 首版范围调整

这轮试验后，首版项目决定暂不再调用模型做自动审核，把有限的时间用于小批量逐条复核、原始数据基线训练和固定划分评测。后续批次默认只调用 Flash 做场景提取与变体生成；程序检查通过的变体进入待复核清单，不能据此直接加入训练集。首批 50 条里，按这个口径有 **12 条待复核**，而非 12 条已合格。

助手对这 12 条做了初步排查：源行 554 的标签翻转、1403 的回复主张扩张，应排除；源行 481 的“且”变“或”、1476 的原始标签依据问题，应隔离；源行 1028、1706、599 仍有原标签或业务动作歧义。源行 1906 的回复未变化，新增信息量低。源行 112、1161、305、1513 未发现明显漂移，但以上均不是已完成的人工复核结论。逐条清单写在本地 `runs/archive/batch/batch-20261002T044310Z/manual_review_queue.md`，包括原文、变体和历史模型意见。先确认可用数量，再决定合成数据是否足以加入训练；即使数量不足，仍可完成原始数据基线与如实记录的数据构建试验。
